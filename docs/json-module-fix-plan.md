# DBX 插件版 JSON 解析模块修复方案

日期：2026-11-10  
状态：代码已实施，自动化回归通过；已生成本地测试包，真实 DBX 安装后的人工验收尚未执行。详见 [修复记录](json-module-fix-results.md)。  
对象：`ui/js/app.js`、`ui/js/json-grid.js` 及其测试、JSON 模块使用的宿主接口。

## 1. 范围与目标

本方案覆盖本轮复查的 9 项已复现缺陷，以及嵌套内容全量预渲染的性能问题。同时纳入会直接影响 JSON 模块的 DBX 存储、保存文件和高级筛选执行限制。

数据库工具、CSV 文件比对、离线校验、发票打印排版等其他模块的问题另行处理。桌面版 WPF 保持独立，本方案可参考其实现，不直接改动桌面版。

目标按以下顺序落实：

1. 数字不变值，表格不显示过期数据，点击不定位到错误值。
2. 保留对象、数组、对象数组、嵌套展开、多页签、格式化、压缩和 CSV 导出能力。
3. 原文、解析结果、筛选结果、页签缓存之间建立明确的版本关系。
4. 在真实 DBX 沙箱约束下验证存储、导出和筛选。
5. 将嵌套展开改为按需渲染，大数组按页显示。

实施时保留工作区已有未提交改动；按阶段提交可复核的变更，不运行发布脚本。

## 2. 已确认问题与修复决策

| 编号 | 优先级 | 问题 | 修复决策 |
|---|---|---|---|
| J01 | P1 | 大整数被 `JSON.parse` 舍入，格式化后原文也改变 | 文档以源码和 token/节点为权威；数字保留原始字面量，格式化不经过 JS Number 序列化 |
| J02 | P1 | 260ms 防抖期间切换页签，产生新原文与旧表格并存 | 输入立即递增文档版本并使表格失效；解析任务捕获 tabId、版本和文本，结果只写回对应版本 |
| J03 | P2 | `/`、`~`、转义键导致原文定位失败或错位 | 解析时统一生成路径及源码区间；渲染器复用节点引用，不再另行拼接路径、二次扫描 |
| J04 | P2 | 筛选重新编号后，点击定位到原数组其他记录 | 筛选结果与源文档分开建模；只允许具有可靠来源映射的节点跳转，无法追溯的新对象禁用跳转 |
| J05 | P2 | JSON 改成非法内容后仍保留旧筛选表格 | 输入立即清空派生结果；解析失败时显示当前版本错误，禁止导出旧结果 |
| J06 | P2 | 根值 `0`、`false`、`null`、空字符串被当成无数据 | 通过解析状态判断是否有数据，取消真假值判断；筛选是否启用使用独立标志 |
| J07 | P2 | 缺失字段读取到原型上的 `toString` 等函数 | 字段只读取自有属性；节点对象采用 Map 或无原型结构，缺失值使用专门标记 |
| J08 | P2 | 嵌套对象导出成 `[object Object]` | 容器单元格导出紧凑 JSON，继续保留数字原始字面量，再做 CSV 转义 |
| J09 | P2 | Tab 缩进未触发解析、状态更新和保存 | 所有文本修改统一进入编辑处理函数，覆盖键盘输入、Tab、格式化、清空和上下文载入 |
| J10 | 性能 | 折叠节点仍全量生成 HTML 和 DOM | 按需生成嵌套表格；数组分页；缓存展开和滚动状态，不缓存整块 HTML |

本轮复现证据：

- `{"id":9007199254740993}` 被读成 `9007199254740992`。
- `{"a/b":11,"a":{"b":22}}` 点击 `11`，实际选中 `22`。
- `[{"id":1},{"id":2}]` 筛选第二条后点击 `2`，实际选中 `1`。
- 编辑后立即切换页签，再切回，出现左侧 `{"new":99}`、右侧仍为 `old=1`。
- `[{"toString":"hello"},{}]` 的第二行及 CSV 出现原型函数文本。
- 5000 条带两级嵌套的测试记录：约 238KB 原文生成约 12.5MB HTML、10001 张表格。此数据是 HTML 生成结果，尚非真实 DBX 的卡顿耗时结论。

## 3. 解析、数字与路径：共用一份文档模型

### 3.1 权威数据

新增独立的 JSON 文档模块，集中负责词法、语法、节点和源码区间。逐步替代 `parseJsonDocument`、`buildPathIndex`、格式化和 CSV 中分散的数据解释逻辑。

每个文档保存：

```text
JsonDocument
  text / revision / status / error
  root
  nodesById

JsonNode
  id / kind
  start / end                 UTF-16 区间，结束位置不包含在内
  keyStart / keyEnd           对象字段键的原文区间
  decodedKey / pointer        解码后的键、统一转义后的路径
  numberRaw                  仅数字节点使用
  children                   保持源码顺序
```

- 字符串与键按 JSON 规则解码；保留原文区间，因此中文、emoji、转义文本均可准确选中。
- 路径段统一按 JSON Pointer 规则转义：`~` → `~0`，`/` → `~1`，根路径使用空字符串。
- 键区间和值区间使用不同字段，不使用 `#key` 等字符串后缀区分，避免与真实键冲突。
- DOM 绑定节点 ID；节点 ID 只在对应文档版本中有效。路径用于展示和状态恢复，不承担全部节点身份职责。
- 重复键不得静默覆盖：文档模型保留重复字段并提示；定位依靠节点 ID。需要普通 JS 对象的筛选遇到重复键时明确拒绝，避免采用隐含覆盖规则。

### 3.2 数字保真

- 数字 token 保存原始文本，例如 `9007199254740993`、`1.2300`、`1e400`。
- 表格显示、JSON 格式化、压缩、嵌套 CSV 序列化均使用原始数字 token。
- 格式化只调整 token 之间的空白和缩进，不将数字转为字符串类型，也不依赖 BigInt 覆盖所有数字。
- 格式化与压缩应保留字符串和键的原始字面量、字段顺序；不主动改写用户数据。
- 向 JS 筛选提供 Number 值前进行显式转换检查。无法保证数值保真的文档暂不执行普通 Number 筛选，给出具体字段和原因；禁止静默近似转换。
- 筛选生成的结果必须是可表示的 JSON；`undefined`、非有限数、循环引用等结果返回明确错误，保留原始文档。

筛选的转换检查比较“原数字字面量”与“转换为 Number 后重新序列化的数字字面量”的十进制值，忽略指数写法和尾零差异；例如 `0.1` 可通过，变值的大整数、长小数、上溢和下溢必须拒绝。不能仅检查 `Number.isSafeInteger`。文档格式化仍保留原始 token，不依赖此筛选转换检查。

## 4. 编辑与页签状态

每个页签分别保存文本、文档版本、解析状态、筛选状态、展开节点、分页位置、编辑器选区和各层滚动位置。

### 4.1 统一编辑入口

用户输入或程序修改文本时，立即执行：

1. 更新当前页签文本并递增 `revision`。
2. 清除该页签的筛选结果和定位缓存，使旧表格不可交互。
3. 更新行号、文本统计和“待解析”状态。
4. 调度解析、独立调度持久化。

保留输入防抖，但回调捕获 `{tabId, revision, text}`；任务完成后只有版本仍匹配才可提交。提交到后台页签不修改当前页面 DOM。后续改为 Worker 时沿用此规则。

切换页签先同步保存文本及视图状态，再取消或隔离旧任务。移除以 `gridHtml` 作为正确性来源的设计，渲染只接受与当前文本版本相同的文档。

### 4.2 状态边界

- 状态区分 `empty / pending / valid / invalid`，与根值内容无关。
- 筛选使用 `{active, sourceRevision, result, provenance}`，不再用 `null` 表示“未筛选”。`return null` 是合法结果。
- 解析失败后显示当前错误；旧表格与旧筛选不能继续显示或导出。
- 清空、关闭最后一个页签、载入示例均重置派生状态。
- Tab 插入缩进后调用统一编辑入口；切换页签与关闭时取消相应定时任务。

## 5. 筛选与原文定位

任意 JS 可以筛选、排序、复制、聚合、修改和构造数据，不能把结果下标直接当成来源下标，也不能用值相等猜测来源。

采用两层策略：

1. 首先止错：筛选结果默认按独立结果查看；未携带可靠来源映射时，原文定位按钮和点击跳转禁用，并提示“结果由筛选生成，无法定位原文”。
2. 再恢复可证明的映射：对于可追踪的原记录选择和重排，返回源节点 ID/路径以及源文档版本。只有确认返回节点内容未发生改写且来源唯一，才允许跳转。新构造对象、聚合值、重复标量保持独立结果。

筛选面板明确标注当前显示“原文”或“筛选结果”；导出遵循当前有效视图。原文一旦修改，筛选和来源映射立即失效。

## 6. 表格、缺失值与 CSV

- 对象数组列取自有字段并集；缺失、显式 null、空字符串、0 和 false 分别处理。
- 已有普通对象兼容接口使用 `Object.hasOwn` 或等价判断，不能直接用 `row[key] !== undefined` 判断字段存在。
- 覆盖 `toString`、`constructor`、`hasOwnProperty`、`__proto__` 等合法键。
- CSV 保留现有列顺序、CRLF、BOM 和引号转义。
- 容器值输出紧凑 JSON，例如 `{"a":1}`，随后对逗号、引号、换行做 CSV 转义。
- 数字使用原始字面量；布尔使用 `true/false`；显式 null 输出 `null`；缺失值与空字符串沿用空单元格。CSV 本身无法完整保留全部 JSON 类型，不宣称能无损回读。
- 空对象和空数组保留合法的空结果显示；导出不能伪造数据行。

## 7. 嵌套与大数组

第一阶段先实现按需展开和分页，按实测决定是否进一步引入虚拟列表。

- 根表格先生成当前页；数组默认每页 100 行，可翻页并保留原始行号。
- 折叠容器只保留节点引用和占位结构，首次展开才创建内部表格。
- 嵌套数组独立分页；收起可移除内部 DOM，保留状态，重新展开时恢复。
- 页签缓存保存展开节点、分页和滚动状态，不复制整段 HTML。
- 深层节点逐级访问，不再用 `MAX_DEPTH=12` 的提示永久阻断后续内容；同时设置明确的解析深度和资源上限，超限报错而非调用栈溢出。
- 解析及纯数据处理迁至 Worker 前，先验证 DBX 的 Worker/CSP 可用性。若受限，使用宿主允许的侧车或分批调度，不假定普通网页的 Worker 能直接运行。

验收以节点规模和可操作性为主，记录实际 Windows/Edge/DBX 版本及时间，不在方案阶段承诺未经测量的毫秒指标。

## 8. JSON 模块的 DBX 宿主兼容

### 8.1 存储

- 封装存储适配层：DBX 使用 `bridge.storage`；独立网页才使用 `localStorage`。
- 等待宿主 ready 后读取，避免异步恢复覆盖已经发生的用户输入。
- 按页签或设置键分别保存，设置写入失败应提示，不得静默报成功。
- 本地参考宿主单值上限为 256KiB，且总容量另有限制；不可把全部 JSON 文本直接塞入一个键。
- 普通设置和小文档走宿主存储；大文档恢复如要保留，使用侧车的插件专属数据目录，并先验证宿主传入目录及文件生命周期契约。该能力未完成时明确提示大文档不会自动恢复，并提供导出，不宣称已保存。

### 8.2 导出

- DBX 使用 `bridge.saveFile`；超出单次适宜大小时检查 `fileTransfer` 支持再采用分块保存。
- 用户取消返回“已取消”；只有宿主确认写入成功才显示“已导出”。
- 独立网页保留 Blob 下载回退。JSON 模块先接入，共用适配器可在后续覆盖其他工具。

### 8.3 高级筛选执行

默认 DBX CSP 禁止 `new Function`，当前浏览器内执行不能作为可发布方案。

建议复用已有 Windows C# 侧车，新增独立 `json/filter` 方法，使用受限 JS 解释器执行；桌面版已有 Jint 和 lodash 使用经验可作为代码参考。此项先做技术验证，再锁定依赖和实现：

- 验证现有筛选示例、lodash、JSON 输入输出、执行超时、语句数/内存/递归限制，以及异常后下一次调用仍可用。
- 不暴露 CLR、文件、网络和打印对象；返回值只允许受控 JSON 与可验证的来源信息。
- 先支持独立结果；跨侧车来源映射必须由明确协议证明，不能依赖引用身份自动跨 JSONL 传输。
- 数字保真、重复键等前置检查与 §3、§5 一致。
- 验证失败时保留原文浏览和导出，筛选入口说明暂不可用；不得将禁用入口视为完整修复交付，也不自动要求用户放宽宿主 CSP。

## 10. 实施顺序与阶段出口

| 阶段 | 内容 | 进入下一阶段的条件 |
|---|---|---|
| A：建立回归样例与修复状态 | J02/J05/J06/J09，文档版本和统一编辑入口 | 快速切页签不串数据，非法输入不显示旧结果，合法根值可浏览 |
| B：共享解析与保真 | J01/J03/J07/J08，节点区间与源码保真序列化 | 大整数和小数不改变，特殊键定位准确，缺失字段和嵌套 CSV 正确 |
| C：筛选与宿主接口 | J04，存储/保存文件；侧车筛选技术验证与实现 | 不发生错误跳转；存储/取消保存/执行限制在 DBX 中通过 |
| D：按需渲染 | J10，移除 HTML 缓存，分页与展开恢复 | 隐藏子树不生成全量 DOM，翻页/切页签状态正确 |
| E：集成验收 | 原有测试、专项测试、真实 DBX 及性能记录 | 全部缺陷验收通过，筛选执行能力完成，才进入打包阶段 |

阶段 A 的快速修复不能替代 B 的保真模型；C 的能力降级只是过渡保护，不计作高级筛选修复完成。各阶段独立验证，减少并行重写产生的定位困难。

## 11. 验收用例

| 范围 | 必测样例/操作 | 通过标准 |
|---|---|---|
| 数字 | 超安全整数、负大整数、长小数、指数、极大/极小指数、`-0` | 显示和格式化/压缩/CSV 中数值 token 不变；不变成引号字符串或 null |
| 原文格式 | 字段顺序、转义键、重复键、中文和 emoji | 只调整空白；节点区间与原文对应；重复键有提示 |
| 路径 | `/`、`~`、引号、反斜杠、`\u0061`、空键、`#key` | 键和值分别精确选中；绝不选到另一个字段 |
| 页签 | 260ms 内编辑并切换、连续切换、后台解析、关闭活动/非活动/最后一个页签 | 文本/表格版本始终一致，不将旧任务写入新页签 |
| 输入 | Tab、撤销/重做、粘贴、格式化、压缩、清空、上下文载入 | 都进入一致的更新流程；保存文本与编辑器一致 |
| 根值 | `0`、`false`、`null`、`""`、`[]`、`{}` | 显示合法数据；可按约定导出 |
| 筛选 | 筛第二条、重排、构造对象、聚合、重复标量、`return null` | 映射可靠才跳转；其他情况明确无来源；结果不覆盖原文 |
| 失效状态 | 应用筛选后改非法 JSON，随后改回合法 JSON | 旧结果立即失效；新解析结果正确；不能导出过期内容 |
| 原型键 | `toString`、`constructor`、`__proto__`，以及后一行缺失字段 | 只显示自有字段；不出现函数、继承值或原型副作用 |
| CSV | 嵌套对象/数组、null、缺失、引号/逗号/换行、大整数 | 容器为 JSON；CSV 转义正确；无 `[object Object]` |
| 沙箱 | `sandbox="allow-scripts"` 与宿主默认 CSP，模拟桥接及真实 DBX | 存储/导出/筛选经允许的接口完成；错误与取消不提示成功 |
| 恢复与容量 | 小文档恢复、超 256KiB 文档、总容量不足、恢复期间用户输入 | 不静默丢失或覆盖输入；容量限制有明确反馈 |
| 筛选资源 | 无限循环、超量结果、异常、后续正常任务 | 受限终止，界面可继续操作，不影响后续筛选或打印 |
| 性能 | 5000 条两级嵌套、10万行简单数组、宽表、超长单行、深层 JSON | 初始仅渲染当前页；折叠子树无内部表格；超限明确反馈 |
| 状态恢复 | 展开两层后滚动、翻页、切页签再返回 | 展开/页码/各层滚动/选区正确恢复 |

性能记录至少包含：输入大小、解析耗时、首屏生成耗时、首次展开耗时、DOM 节点数量、交互是否可取消。区分纯函数测试、浏览器测试与真实 DBX 测试结果。

现有 `test-grid.mjs`、`test-ui.mjs` 继续保留；新增断言必须能击中上述缺陷，不能只检查界面存在或函数返回。时间竞争测试应使用可控制调度或明确的版本断言，避免单靠固定 sleep。
